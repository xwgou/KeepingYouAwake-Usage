Codex
https://learn.chatgpt.com/docs/app-server
Official documentation supports structured account rate-limit reads and updates,
with separate quota buckets and windows. The proposed integration uses that
protocol instead of scraping /status. Local codex-cli is 0.167.0; its help exposes
app-server and schema generation. Runtime compatibility and account access have
not been tested. API-key billing must not be presented as ChatGPT quota.

Kimi
https://www.kimi.com/code/docs/en/kimi-code-cli/reference/slash-commands.html
https://www.kimi.com/code/docs/en/kimi-code-cli/reference/kimi-command.html
https://www.kimi.com/en/help/kimi-code/membership-guide
https://www.kimi.com/en/help/kimi-code/faq
Current docs identify /usage for quota and distinguish Kimi Code membership
from pay-as-you-go Open Platform billing. They describe migration from the older
Python client to the Node client. Local kimi is 2.4.1: help includes acp and web,
but no dedicated usage subcommand. ACP existence alone does not establish a quota
API. No supported machine-readable quota contract was verified in this task.

Design assumptions requiring implementation validation
The companion approach, refresh intervals, menu layout, compatibility policy,
and effort estimates are proposed engineering choices, not provider guarantees.
No real account data was read and all example usage values are fictional.
