Phase 2 — menu and data model (1–2 days, after baseline)

Phase 3 — adapters and refresh lifecycle (2–3 days, after Phase 1 gate)

Connect coordinator to NSMenu updates; add manual refresh and dashboard links.
Exit: actual usage matches each provider's own UI for the same account/time,
allowing documented refresh delay. Monitoring performs no inference requests.

Phase 4 — regression, packaging, and handover (1–2 days)
Add focused XCTest coverage; run the existing default and sanitizer plans.
Manually check click routing, timer expiration, launch/login, URL automation,
sleep/wake, disconnect/reconnect, CLI upgrade, network outage, VoiceOver, keyboard,
light/dark appearance, and Intel/Apple Silicon compatibility where supported.
Select one product name and create a distinct icon. Change app/helper bundle IDs,
URL schemes and login-item references consistently. Replace or disable upstream
Sparkle feeds and signing keys for the fork before distributing any test build.
Retain MIT notices. Document install, CLI prerequisites, connection, and uninstall.
Exit: signed install works on the supported OS range and updater cannot replace
this fork with the upstream app. Unavailable hardware checks remain explicit.

Makefile test recipes require xcbeautify and resolved packages. Unsigned builds
are compile checks only; sandbox, helper IPC, Keychain, and distribution checks
require suitable signing. Do not infer runtime success from a successful build.

Test matrix and release acceptance
- Parsers: missing/null/extra fields, multiple buckets, zero/invalid limits,
  invalid percentages, units, reset timestamps, and unsupported versions.
- Coordinator: simultaneous opens create one request per provider; timeout,
  rate limiting, wake, and failure do not leak subprocesses or block the main UI.
- Accounts: switch during an in-flight request discards the old response;
  disconnect clears app-owned cache without changing the CLI login.
- UI: both providers visible with independently accurate state; 0% and unknown
  are distinguishable; stale data retains its true timestamp.
- Regression: menu open has no timer effect; explicit toggle, durations, legacy
  clicks, and existing automation still work.
- Full feature completion requires live Codex AND Kimi usage in the menu. A mockup
  or dashboard-only mode must be labeled a partial prototype.
